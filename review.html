🏗️ Отчет по проекту: Modular Monolith Payouts System

1. Обзор архитектуры

Приложение построено по принципу Modular Monolith на современном стеке Django 6.0 + Django Rest Framework. Каждый бизнес-домен вынесен в отдельное Django-приложение (модуль), что позволяет в будущем легко перейти к микросервисам или поддерживать строгую изоляцию логики.

🧩 Основные модули (Apps)

МодульНазначение

2. Имеющийся функционал и логика

🔐 А. Управление пользователями и ролями (iam)

  • Ролевая модель: Реализованы роли: Admin Manager Accountant Contractor.
  • Компании (Multi-tenancy): Пользователи (кроме системных админов) привязаны к Company. Это обеспечивает полную изоляцию данных между разными организациями.
  • Аутентификация: Используется JWT (djangorestframework-simplejwt) для защиты API.

⚙️ Б. Жизненный цикл задачи (tasks)

  1. Создание: Менеджер компании создает задачу (Task) с указанием бюджета и описания.
  2. Поиск: Исполнители (Contractor) видят список доступных задач своей компании.
  3. Принятие (Accept):
    • Когда исполнитель принимает задачу, срабатывает бизнес-логика в tasks/services.py.
    • Если у задачи нет привязанного контракта, система автоматически создает контракт на основе шаблона компании.
    • Статус задачи меняется на Accepted.

📄 В. Система контрактов (contracts)

  • Шаблоны: Компании могут создавать ContractTemplate с текстом договора.
  • Генерация номеров: Реализован сервис автоматической генерации номеров контрактов (Формат: CMP{id}-{year}-{sequence}).
  • Подписание: Реализован Endpoint для подписания контракта исполнителем. Только после подписания контракт считается юридически значимым в системе.

3. Логика приложения (Workflow)

🚀 Ключевая "фишка" текущей реализации — автоматизация бюрократии.

Как только исполнитель нажимает "Принять задачу", система берет на себя создание юридических документов.
Это исключает работу "без договора", ускоряет процесс взаимодействия между заказчиком (Company) и исполнителем (Contractor).
👔 Менеджер → Создает задачу
🧑‍💻 Исполнитель → Принимает задачу
⚙️ Система → Автоматически создает контракт
✍️ Исполнитель → Подписывает контракт
💰 Модуль Payments → Готов к оплате

4. Будущие нововведения (Roadmap)

На основе анализа пустых модулей и структуры проекта, планируется следующий функционал:

📂 1. submissions (Сдача работ)
  • Загрузка отчетов о выполненной работе.
  • Процесс ревью: Приемка / Отклонение результата менеджером.
💳 2. payments (Выплаты)
  • Интеграция с платежными шлюзами (Stripe, ЮKassa и др.).
  • Автоматическое формирование счетов после одобрения submission.
  • Отслеживание статусов оплат.
📑 3. documents (Документооборот)
  • Генерация PDF-файлов на основе шаблонов (ContractTemplate).
  • Хранение подписанных документов в облачном хранилище (S3).
🔔 4. notifications (Уведомления)
  • Email / Telegram уведомления о новых задачах, подписании контрактов и поступлении оплаты.
📊 5. analytics (Аналитика) — предложение
  • Дашборды для бухгалтеров и менеджеров по расходам компании.
